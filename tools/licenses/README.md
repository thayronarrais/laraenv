# Desktop dependency notices

Run from a checkout with the locked frontend and screenshot packages installed and the required Go module sources already cached:

```powershell
node --test tools/licenses/*.test.mjs
node tools/licenses/generate.mjs --go-bin 'C:\path\to\go1.26.10\bin\go.exe'
node tools/licenses/generate.mjs --check --go-bin 'C:\path\to\go1.26.10\bin\go.exe'
```

Use the exact Go version used for the release, Node/npm versions used to install the lockfiles, and matching dependency trees. The Windows directory-junction fixture needs junction creation permission; the sandbox may deny that fixture even when normal file tests run. No test downloads or executes PHP/Composer, installed runtimes, or downloaded tools.

The generator runs only Go metadata commands with `GOTOOLCHAIN=local`, `GOPROXY=off`, `GOSUMDB=off`, `GOWORK=off`, `-mod=readonly`, amd64, and CGO disabled. It never installs or downloads missing dependencies. Missing required Go sources or frontend runtime packages cause a failure; prepare the caches in a separate, explicitly authorized dependency-install step.

`policy.json` specifies release graph tags, exact version/hash-bound exceptions, and preserved supplemental texts. It is part of the generated input digest. The current graph uses Wails' browser prerequisite strategy. Pass the same strategy to the release build; changing that policy alone does not change a compiled artifact. Review any changed Composer PHAR or Monaco version before updating their pinned policy. The PHAR parser reads bounded container entries, decompression, lengths, and CRCs; it never evaluates PHP or deserializes metadata, and does not authenticate the PHAR's OpenSSL signature.

Outputs are `THIRD_PARTY_NOTICES.txt`, `third_party/dependencies.json`, and exact upstream license/NOTICE bytes under `third_party/licenses/<sha256>.txt`. The aggregate includes all unique full text sections, resource attribution, and available corresponding-source URLs so an offline in-app text viewer can display the full notice bundle. `--check` recomputes in memory and detects missing, changed, and extra generated files without writing. Normal generation replaces the generated output tree's files; keep hand-authored material in `tools/licenses/notices/`, never in `third_party/`.

WiX UI/Util 5.0.2 custom-action resources used by the MSI are separately identified under MS-RL. Their official NuGet package hashes and the matching cached extension DLL hashes are pinned in policy, along with source commit `aa65968c419420d32e3e1b647aea0082f5ca5b78`. The unmodified official source archive is preserved at `tools/licenses/sources/wix-5.0.2-source.zip` and copied to `third_party/sources/`. Deliver that archive and the full MS-RL with the MSI; a license label or source URL alone does not replace source delivery. No extra licensing exception was found in the versioned license/source review. The installer resources retain MS-RL separately from original desktop code.

Git attributes must pin tracked generator inputs to LF and treat preserved upstream notice/source files as binary (`-text`). The aggregate is rendered with canonical LF; its individual content-addressed upstream files preserve exact original bytes, including CRLF. Normalize only the aggregate, never the source evidence or its hashes.

Whitespace checks are disabled only for preserved third-party legal texts and their rendered aggregate. Upstream trailing spaces, CRLF and final blank lines are intentional evidence; do not reformat them to satisfy `git diff --check`. Application code and other project files retain normal whitespace checks.

The inventory covers all explicit Go requirements and selected Windows desktop/Windows and Linux TUI module closures, plus all frontend non-dev dependencies. Installed dev/build package notices are retained conservatively. Unavailable platform-specific optional build packages and unexpanded Go test/tool-only module nodes remain explicit metadata-only entries. Presence in the inventory or heuristic identification of standard license text is not a legal compatibility determination or a claim that the dependency is linked into every executable. The exact release binaries and their copied frontend/installer payload still require artifact verification.

Monaco's complete AMD tree is distributed outside normal Rollup imports; its root license, bundled third-party notice file, worker dependencies, and Codicons font notice are preserved. JetBrains Mono's OFL text remains separate. Composer's root and vendor package terms are supplemented by the separately licensed Mozilla CA store and Unicode data attribution; the helper EXE stays a separately identified, hash-pinned package resource.

The root Apache license applies to original desktop code. Optional catalog downloads, Microsoft WebView2/VC prerequisites, separately released pgvector ZIPs, and any later mirroring/repackaging retain separate obligations. `runtime-policy.json` contains the reviewed catalog, every pinned PECL/PHP-series build and platform prerequisite findings. The collector verifies all five reviewed Go source hashes using the policy's declared CRLF-to-LF normalization, checks complete exact coverage and rejects duplicates or missing rows. Changes to catalog versions, URLs or prerequisite behavior require a policy review. Generation still hashes actual input bytes; tracked source inputs use LF. The generator does not produce a standards-compliant SPDX/CycloneDX SBOM; `dependencies.json` is its documented custom evidence inventory.

Inventory schema version 1 now also carries `runtimeReview` with the review date, scope, retention verification and all historical warnings. Each optional runtime/PECL/platform entry has `reviewedSoftwareLicense` (a descriptive string, not necessarily SPDX), its primary sources, binary evidence limits, required actions and redistribution status. `declaredLicense` stays null for these unbundled or proprietary scope entries. `downloadEvidenceStatus` distinguishes an exact archive review from a component-level representative review. Representative evidence never silently clears other PHP series, versions or companion binaries. Required source/corresponding-source obligations and published-asset omissions stay visible after local retention tests pass.

The six `embedded-runtime-notice` components are different: the desktop actually embeds those upstream text files. Their strict SPDX identification, raw SHA-256, byte length, exact source URL and runtime version scope are pinned. Collection verifies that the notice/version combinations exactly match the installer's supplemental retention map. Their content-addressed output files preserve every byte, including any CRLF. PostgreSQL, Redis fork/core, jemalloc, Lua and hiredis notices supplement identified omissions; they do not certify a complete binary dependency inventory or repair existing public downloads. The policy, collector, reviewed source files, retention implementation and six original notice paths are all part of the generated input hashes. Large downloaded ZIPs and ignored audit evidence are not copied into outputs.

The optional `publications` policy field records a separately verified release repair without deleting historical warnings. The collector currently accepts only the reviewed pgvector 0.8.6 repair: fixed repository/release identity, four exact catalog version/URL pairs, unique asset IDs, valid SHA-256 values, the matching upstream license and linked checksum names/URLs. Checksum text hashes and byte counts are derived locally from the recorded archive digests. Evidence paths remain relative references; collection neither downloads assets nor reads ignored audit evidence. This checks consistency of the human-reviewed record, not its authenticity or binary provenance. Older policies can omit this field.

`runtimeReview.publications` preserves those records in the inventory. The offline aggregate shows publication hashes, evidence limits and each warning's optional `status` and `resolution.summary`/`evidenceReference`; absent dispositions are labeled “not recorded.” A resolved notice omission keeps its original reason and required action as history, alongside the recorded resolution. Other runtime/source/companion obligations keep their own status.

The optional `peclNoticeRegistry` pins the raw hash of `internal/installer/pecl_notices/manifest.json`. Its bundles must match exact PECL extension/version/PHP-series/catalog URLs and identify the archive SHA-256. Every supplied `.txt` must appear exactly once in that registry, with its exact hash, size, HTTPS source and descriptive license terms. Missing, extra, duplicate or aliased files stop collection. Registry, notice and retention-helper paths join the generated input digest; no original runtime ZIP or ignored evidence is read. `runtimeReview.peclNoticeRegistry` retains the metadata, while `embedded-pecl-notice` components preserve the original text bytes. These heterogeneous notices use `declaredLicense: null` and `required: false`; their hashes remain mandatory, and their scope explicitly excludes complete binary clearance.

The optional `catalogNoticeRegistry` applies the same rules to `internal/installer/runtime_notices/manifest.json`, scoped by catalog kind/version/URL and exact archive hash. `embedded-catalog-notice` components and `runtimeReview.catalogNoticeRegistry` retain that evidence. Redis notices use a separate bundle directory below the existing version-bound legal folder, preserving the previous manifest on upgrades/retries. The fingerprint comes from the same opened archive used by ZIP extraction. Each registry accepts at most 64 bundles and 256 notices per bundle, with 8 MiB per text and 32 MiB combined per bundle, matching installer bounds.

Optional `sourceEvidence` is human-reviewed provenance, carried verbatim into installed manifests, inventory and offline aggregate. It records source hashes, complete comment byte ranges/origins or historical source selection limits where available. The registry hash binds these records; the collector does not authenticate source URLs, reconstruct source excerpts or certify that candidate source produced a binary. Independent byte/source review remains necessary when changing this data. Redis includes 100 additional texts; the three PECL bundles include seven MongoDB, one memcached and 69 Imagick texts. The original upstream/archive manifests and earlier eight PECL files remain unchanged. Full LGPL notices/recipient modification rights are distinct from delivering a usable source/relink route for a future binary redistribution.
