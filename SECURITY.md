# Security reports

Please report suspected vulnerabilities privately. Do not put credentials, private keys, personal data or an exploit against a real system in a public issue.

## Report a vulnerability

Open the repository's [Security tab](https://github.com/thayronarrais/laraenv/security) and use **Report a vulnerability** if GitHub private vulnerability reporting is available. Availability depends on the repository settings; this document does not establish that the feature is enabled.

If private reporting is unavailable, email the maintainer at [thayron.arrais@gmail.com](mailto:thayron.arrais@gmail.com) with the subject `LaraEnv security report`. Start with a concise description and a safe reproduction using fictional data. Arrange an appropriate way to share any sensitive material before sending it.

Include the affected version or source commit, Windows version, relevant configuration, expected security boundary, impact and reproduction steps. State whether the issue needs cloud integration, administrator access, local MCP access, a downloaded runtime or a particular remote service. Report vulnerabilities in third-party components to their maintainers as appropriate, and explain how LaraEnv is affected.

## Scope and response

This policy covers the LaraEnv desktop source and its included integrations. The hosted backend is maintained separately and is outside this source distribution. The project does not publish a fixed support window, response-time commitment or bounty program in this policy. Include the exact affected version even if you can reproduce only on an older release.

Local operations can manage processes, files, credentials, databases and remote hosts. Reproduce issues only against systems and data you control. A build or source review is not evidence that a published package has passed installation, upgrade or security testing.
