Afirmações de omissão/indisponibilidade abaixo descrevem os bytes/URLs originais, preservados como histórico; a política e o relatório atual registram suas disposições.

Esta revisão cobre as **40 fontes de 13 tipos** em `internal/installer/catalog.go`, as **41 combinações de seis extensões PECL** em `internal/installer/pecl.go`, as referências do Visual C++ Redistributable e a descoberta/bootstrap do WebView2. A [política legível por máquina](../../../tools/licenses/runtime-policy.json) registra versões, URLs, obrigações, hashes de evidência, avisos e hashes dos arquivos de entrada normalizados para LF. O Composer 2.8.5 embutido continua sob a política existente; WiX e dependências do backend privado não foram reavaliados aqui.

**Resultado:** as licenças principais foram identificadas; isso não libera indiscriminadamente todos os binários para redistribuição. Foram inspecionados como dados 25 ZIPs públicos exatos, incluindo o fonte do fork Redis; duas tentativas de ZIP PHP retornaram 404. Os quatro ZIPs pgvector publicados pelo projeto não contêm a licença exigida pelo upstream. O ZIP Redis também omite `license.txt`, apesar de seu README dizer que o inclui. As amostras PECL contêm material legal que não pode ser descartado ao instalar apenas DLLs.

Nenhum PHP, PHAR, executável ou instalador baixado foi executado. Nenhum runtime operacional do usuário, backend, credencial ou configuração privada foi inspecionado. Não houve publicação, espelhamento ou alteração dos assets públicos.

## O que efetivamente é distribuído

O catálogo descreve downloads opcionais efetuados no computador do usuário. Isso é diferente de incluir esses arquivos no MSI, no executável, num mirror ou num release do projeto. Os avisos do desktop não mudam as licenças desses produtos. Os quatro assets pgvector são diferentes: seus binários Windows já são oferecidos pelo próprio repositório de releases do projeto.

Apache e PostgreSQL usam seleção/download manual. O endereço EDB é uma página móvel, sem identidade do ZIP selecionado pelo usuário; a versão escrita no catálogo não autentica seu conteúdo. A implementação `vcruntime` apresenta links Microsoft e não baixa, extrai ou instala o redistributable. A recuperação WebView2 seleciona uma instalação gerenciada pela Microsoft, sem copiar seu runtime. O build desktop usa a estratégia de bootstrap `browser`; o runtime permanece um pré-requisito separado.

Preservar um texto de licença, identificar a licença do projeto e demonstrar conformidade de um conjunto específico de binários são verificações distintas. Os hashes abaixo identificam os bytes examinados; não autenticam o publisher, não provam correspondência fonte/binário e não substituem uma análise de bibliotecas estáticas ou acompanhantes.

O instalador agora conserva o material fornecido com os mesmos bytes e caminhos relativos aninhados em `licenses/pecl/<extensão>/<SHA256-do-ZIP>/files/`, acompanhado de manifesto e hashes. As fixtures passaram para LICENSE, NOTICE, THIRD_PARTY_NOTICES, COPYING, README e OFL, incluindo caminhos aninhados. Entradas inseguras, aliases duplicados e textos acima dos limites são rejeitados antes de gravar DLLs; documentos diferentes já existentes são preservados. O manifesto distingue arquivos preservados de material não fornecido pelo ZIP. Essa retenção **não corrige notices que já faltam no ZIP** nem dispensa fonte correspondente.

Seis textos upstream exatos são embutidos e suplementados somente para pgvector 0.8.6-pg15/16/17/18 e Redis 5.0.14.1, em `licenses/laraenv/<tipo>/<versão>/`. O manifesto os identifica como avisos de fonte suplementares, sem certificação do conjunto de binários. O namespace é reservado: ZIPs que tentem sobrescrever esses avisos ou os manifestos PECL são rejeitados antes da extração. A política e o inventário validam os seis hashes, fontes e escopos contra a implementação. Os [resultados de validação](runtime-dependency-verification.md) documentam os testes e os artefatos.
