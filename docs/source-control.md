# Controlo de versões do workspace

Na página Terminal, **Git** abre o controlo de versões do projeto ou worktree da shell selecionada. A barra partilhada permite alternar entre **Agentes**, **Ficheiros** e **Git** sem reiniciar terminais nem descartar documentos. A origem apresentada identifica o checkout efetivo; mudar de terminal não transfere uma operação já iniciada para outro repositório.

O painel apresenta separadamente alterações preparadas no índice e alterações no disco. Um ficheiro modificado nas duas camadas aparece nas duas listas: a comparação preparada é HEAD → índice; a comparação do disco é índice → disco. As comparações Git são apenas de leitura e mantêm os seus próprios modelos, separados dos buffers editáveis. Binários, texto não suportado, ficheiros acima de 2 MiB por lado e referências de submódulos têm um resumo explícito, em vez de uma comparação vazia.

Selecione ficheiros e use **Adicionar selecionados**, ou a ação do próprio ficheiro. **Retirar do índice** conserva o conteúdo do disco. Se houver alterações por guardar no editor, escolha **Guardar e adicionar**, **Adicionar versão do disco** ou **Cancelar**. A primeira opção verifica novamente a geração e o estado do buffer depois de guardar; uma alteração entretanto feita impede a preparação de uma versão que deixou de estar revista. A segunda prepara os bytes atuais do disco e mantém o buffer por guardar. O diálogo bloqueia ações concorrentes e atalhos dirigidos ao workspace.

O commit inclui **todo o índice revisto do checkout**, mesmo que a pesquisa ou seleção mostre apenas alguns ficheiros. Não guarda automaticamente buffers, não usa `-a` e respeita hooks e assinatura Git. Uma falha conserva a mensagem e mostra a saída limitada da operação. Um commit bem sucedido nunca inicia um push automaticamente.

Para enviar, escolha explicitamente um remoto e a branch de destino; **Push** é uma ação separada. Pode definir esse destino como upstream. Não são usados force, tags, pull automático nem envio recursivo de submódulos. A autenticação usa a configuração e os auxiliares normais do sistema, sem pedir ou guardar segredos no painel e sem prompt interativo Git. Uma falha ou cancelamento pode deixar o resultado remoto incerto; consulte o resultado e atualize o estado antes de repetir.

O estado é atualizado a cada dois segundos quando o painel e a janela estão ativos. Operações mutáveis são serializadas por diretório Git comum, incluindo linked worktrees, e respeitam locks externos do Git. A raiz deve corresponder ao repositório autorizado pelo catálogo ou sessão; repositórios ancestrais, internos e submódulos não recebem autoridade implícita. Revalidações de identidade, HEAD, índice e revisão de disco reduzem corridas com escritores externos, mas não constituem uma transação com ferramentas que não cooperem nem garantem que um pathname continue estável após movimentos externos.

Minimizar para a bandeja conserva operações em curso. Sair ou instalar uma atualização é recusado durante uma operação Git ativa, sem a abandonar silenciosamente. Os tempos máximos são 30 s para consultas, 60 s para adicionar/retirar ficheiros, 120 s para commit e 180 s para push; a saída apresentada é limitada a 64 KiB e os pipes continuam a ser drenados.
