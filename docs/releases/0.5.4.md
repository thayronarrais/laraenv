# LaraEnv 0.5.4 — files, Markdown and Git alongside your agents

This release brings file editing and source control into the terminal workspace, adds optional local MCP access for assistants, and lets you choose whether a deployed database accepts remote connections.

## A workspace for agents, files and Git

Agents, Files and Git share one sidebar with tabs. You can hide the navigator, collapse the main navigation, resize panels and show or hide the editor while terminal sessions remain open. Panels use subtle corners and consistent spacing, including on the Dashboard.

The file browser lists folders before files. Open text files in the editor, switch Markdown between source and preview, and preview supported images. Document tabs remember their project or agent worktree. Saving detects external changes, and closing or quitting prompts when unsaved work needs a decision.

The Git panel follows the selected checkout. Expand or collapse changed folders, review staged and working-tree diffs, stage or unstage files, write a commit message, and push to the selected remote and branch. Commit includes the checkout's staged index. Push remains a separate action. Successful operations use one compact confirmation with expandable history; failures and running operations remain visible.

## Terminal improvements

Copy and paste use the Windows clipboard bridge with fallback and visible failures. The command palette can focus existing local, SSH and agent terminals. Focus and workspace context are preserved across terminal panes and document views.

## Optional local MCP access

Enable MCP in **Settings > Experimental** and register Claude Code, Codex or Cursor. It is disabled by default. Assistants can inspect projects and runtimes, operate services and workers, run project commands, read logs, manage supported local databases, and request diagnostics. Commands report progress and results; actions requiring confirmation keep their confirmation step.

Registration preserves other client settings and backs up existing configuration files. Restart the assistant after registering it, and keep LaraEnv open under the same Windows account.

## Choose remote database access during Apply

The deployment form now includes **Allow remote database access** for MySQL and PostgreSQL. It is off by default. When enabled, provide individual source IP addresses; Apply configures access for those addresses. Reapplying with the option off revokes access managed by this deployment. The option is applied during Apply rather than each automatic Git pull.

## Downloads

- **Installer:** `LaraEnv-0.5.4.msi` for Windows 10/11 x64.
- **Portable:** extract `LaraEnv-0.5.4-portable-win64.zip` and run `LaraEnv.exe` from its folder.
- Matching `.sha256` files are included. The separate `LaraEnv.exe` asset supports the in-app updater.

This public release follows **v0.5.3**. Higher patch numbers used for local test installers were development builds.

If you installed a local test MSI numbered 0.5.5–0.5.12, uninstall that test application before installing 0.5.4: Windows Installer treats it as a newer version and blocks an in-place downgrade. The normal upgrade from public v0.5.3 is unaffected.
