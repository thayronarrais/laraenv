# LaraEnv 0.5.6 — project commands and Agent map

Released on **2026-10-16**, following public **v0.5.5**.

## Run commands from the project panel

The selected project's panel now reads the scripts declared in `package.json`. Choose `dev`, `watch`, `build` or any custom script name that exists in the manifest, then run it with the project's resolved package manager: npm, pnpm, Yarn or Bun. Refresh the selector after editing the file; read failures offer a retry.

Use **Custom command** to run another command in the project directory. Scripts and custom commands open a new integrated terminal with the project's saved shell and effective PHP/Node runtimes. Output stays visible when a task finishes. Use **Ctrl+C** in that terminal to stop continuous scripts.

These actions do not overwrite the saved Dev command or append server arguments such as `--port` to a task like `build`.

## Development and Laravel queues

Managed **Dev** controls are available for projects with `package.json`, even when LaraEnv does not recognize a framework. Start or stop the managed process, inspect its logs and configure its command from the panel.

Laravel projects keep their **Queue worker** controls visible independently of Node scripts. Start, stop or restart the worker and configure its arguments from the queue menu.

Read the [Projects guide](https://github.com/thayronarrais/laraenv/blob/main/docs/projects-workspace.md).

## Inspect agent activity

Optional agent sessions now have an **Agent map**, opened from the footer activity counter or a session's **View map** action. Inspect the selected session's observed descendants and background tasks, select a node for available details, and return to the principal terminal. The main and detached workspaces share activity snapshots.

Claude Code and Codex observation depends on the provider protocol and trusted hooks. Kimi and OpenCode report child observation as unavailable. The map describes activity observed during the current run and keeps it in memory; unknown states and missing model, duration or token data are shown as unavailable rather than inferred. Enable agent sessions in **Settings → Experimental**.

- The footer no longer keeps a stale activity chip when there is no eligible current session or its observation has ended. Opening a historical map explicitly still shows its observation limits.

## Downloads and upgrades

- Windows 10/11 x64 installer: `LaraEnv-0.5.6.msi`.
- Portable edition: extract `LaraEnv-0.5.6-portable-win64.zip` and run `LaraEnv.exe` alongside the `.laraenv-portable` marker.
- The separate `LaraEnv.exe` asset supports the portable in-app updater. Each asset has a matching `.sha256` sidecar.

Close LaraEnv before installing. The normal upgrade from public **0.5.5** is supported.

If you installed a local test MSI numbered **0.5.7–0.5.20**, uninstall that test application before installing **0.5.6**: Windows Installer blocks an in-place downgrade. Preserve `C:\laraenv`, your portable folder and your project/database data. Uninstalling the application is not a request to delete that environment. The higher test numbers were development builds, not public releases.
