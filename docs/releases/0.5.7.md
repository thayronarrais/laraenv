# LaraEnv 0.5.7 — SSH trust, local HTTPS and Laravel context

This release follows public **0.5.6** and improves Windows reliability, local HTTPS and the evidence available to connected assistants.

## SSH server identity and saved passwords

Integrated SSH, SFTP, deployment transports and jump hosts now use LaraEnv's existing OpenSSH `known_hosts` file. A first-seen key is saved; matching keys are accepted; changed or revoked keys stop the connection. Servers with several host-key types prefer an already trusted type. Verify a server's fingerprint independently before intentionally changing its saved trust.

Saved SSH passwords are protected with Windows DPAPI for the current account. Legacy migration preserves the original configuration if protection or persistence fails. Moving a portable environment to another Windows account can make a password unavailable: the host and protected bytes are retained, and the interface asks for a replacement. An unavailable password is never uploaded as an empty cloud replacement. Other configuration fields and private-key files are outside this password protection.

## Local HTTPS across PHP and Node

PHP trust bundles can include LaraEnv's public local CA while preserving custom trust settings. New project processes receive Node's local-CA environment; compatible Laravel Vite setups can receive the existing site's certificate variables. Explicit project settings take precedence, and HTTP reverse-proxy upstreams retain their current configuration.

HTTPS actions now show progress and outcomes alongside the project and prevent duplicate actions. Failed configuration changes preserve the previous preference and managed files. Portable copies continue to ask explicitly before trusting the local CA in Windows. Existing CA material is preserved; a partial or mismatched CA produces a recovery error instead of silent replacement.

## Experimental Laravel context for assistants

The optional local MCP connection adds `laraenv_context`, a diagnostic prompt and a project-context resource. Assistants can inspect bounded single/daily Laravel logs, explicitly attributed Mailpit messages and previously collected runtime metadata. The existing project, service, worker, command, database and diagnostic tools remain available.

A separate, confirmed project integration can install a provider and configuration for review. It requires explicit registration and local opt-in before collecting request, query, job, view, log and dump metadata. It excludes SQL text/bindings, request bodies and dump values. It also offers a companion guideline that can coexist with Laravel Boost; installing it does not install Boost or execute the project.

MCP and agent sessions remain experimental. The collector was verified with real Laravel 12 libraries and PHP 8.5; Laravel 10, 11, 13, Octane and other long-lived request servers remain unverified. No provider is installed or activated automatically.

## Startup and configuration reliability

The terminal workspace starts shells and resumes agents only after first activation or an explicit request. Saved layouts remain available without launching background shells at application startup.

When normal WebView2 discovery fails, LaraEnv can select a validated Microsoft-signed machine runtime for its own process. It does not repair the Windows registry or change the system's WebView2 installation. Atomic configuration replacement also preserves existing Windows access permissions.

## Downloads and upgrades

- Windows 10/11 x64 installer: `LaraEnv-0.5.7.msi`.
- Portable edition: extract `LaraEnv-0.5.7-portable-win64.zip` and run `LaraEnv.exe` next to `.laraenv-portable`.
- The separate `LaraEnv.exe` is the portable updater payload. All three assets have matching SHA-256 sidecars.

Close LaraEnv before installing. Normal upgrades from public **0.5.6** are supported. If you installed a local test MSI numbered **0.5.7 or higher**, uninstall that test application before installing stable 0.5.7. Preserve `C:\laraenv`, portable folders, projects and database data.

Local development remains free. Optional cloud sync and deployments keep their existing Pro plan. This release does not change source-code availability or licensing.
