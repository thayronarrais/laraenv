# LaraEnv 0.5.5 — project runtimes, Site Doctor and a clearer Projects page

Released on **2026-10-12**, following public **v0.5.4**.

## Projects that stay manageable as the list grows

Projects now uses a compact list with search by name, path or tag, client-tag filtering with counts, and pages of 10, 20 or 50 projects. Selecting a row opens one details panel with quick launch, runtimes, development processes and project tools. In smaller windows the panel opens over the list and can be closed with Escape.

Choose the two row shortcuts under **Customize actions**: editor, browser, terminal or folder. Hide either shortcut, change their order or restore the defaults. The choice is saved on this device; editor and terminal actions respect the project's existing preferences. List, panel, buttons and selection use the selected theme.

Web-server status describes the shared server. PHP pools remain shared by version. **Start Dev** and **Start queue** control the selected project's processes; the page does not present every project as an independently running server.

## Automatic PHP and Node selection

LaraEnv reads project requirements before starting a new terminal, agent, dev server, queue, scheduled job or supported MCP command:

- PHP: manual project selection, then `.php-version`, then `composer.json` `require.php`, then the global runtime.
- Node: manual project selection, then `.nvmrc`, `.node-version`, `package.json` `engines.node`, then the global runtime.
- Package manager: `package.json` `packageManager`, then a lockfile, then npm.

Automatic selection uses the highest compatible verified stable installation. The panel shows the selected version, its source and the requirement. Missing compatible versions link to the filtered Downloads page. Invalid requirements are reported instead of silently using an incompatible global runtime. Choosing **Automatic** removes a manual override.

Runtime declarations are refreshed after creation, cloning and relevant file changes, including registered worktrees. Existing terminals and workers keep their runtime until restarted. Changes to served PHP configurations preserve the previous configuration when the required runtime cannot be applied.

## Site Doctor

Run **Doctor** for one project or **Run Doctor on all sites** for an overview. The overview groups healthy projects and projects needing attention, with search, pagination and one project's findings at a time.

Checks cover runtimes, dependencies, Laravel `.env` and application key, optional storage link, WordPress configuration, supported local databases, migrations, virtual hosts, hosts entries and PHP-FPM. Available repairs run individually, stream their output and recheck the affected project. Migrations and replacement of a customized virtual host require confirmation. A running repair can be cancelled.

The Laravel storage link is optional and does not make an otherwise healthy project fail. Existing files, directories and links to other targets are preserved; Windows junctions to the standard public-storage directory are recognized. Uncertain database results and configurations that cannot be inspected appear as **Skipped**, rather than a confirmed failure. A healthy result describes the completed checks, not an end-to-end test of the application.

Guides: [Projects](https://github.com/thayronarrais/laraenv/blob/main/docs/projects-workspace.md), [runtime detection](https://github.com/thayronarrais/laraenv/blob/main/docs/project-runtime-detection.md), [Site Doctor](https://github.com/thayronarrais/laraenv/blob/main/docs/site-doctor.md).

## Downloads and upgrades

- Windows 10/11 x64 installer: `LaraEnv-0.5.5.msi`.
- Portable edition: extract `LaraEnv-0.5.5-portable-win64.zip` and run `LaraEnv.exe` alongside the `.laraenv-portable` marker.
- The separate `LaraEnv.exe` asset supports the portable in-app updater. Each of the three assets has a matching `.sha256` sidecar.

Close LaraEnv before installing. The normal upgrade from public **0.5.4** is supported.

If you installed a local test MSI numbered **0.5.6–0.5.18**, uninstall that test application before installing **0.5.5**: Windows Installer blocks an in-place downgrade. Preserve `C:\laraenv`, your portable folder and your project/database data. Uninstalling the application is not a request to delete that environment. The higher test numbers were development builds, not public releases.

## Inspection limits

Database probing uses recognized literal configuration and the effective PHP. Automatic database creation is limited to supported local MySQL/PostgreSQL targets on their default ports, using the project's credentials. Dynamic or cached settings, external connections and unavailable probes remain unverified. Corrections are offered only when their prerequisites are satisfied; not every finding has an automatic repair.
